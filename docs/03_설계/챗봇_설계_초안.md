# 챗봇 설계 초안 v0.2 (2026-10-27)

고배당 분리과세 점검 챗봇(add-on)의 로직·제한·예외 처리·답변 구조·정확성·RAG·가드레일·사용 편의를 한곳에 정리한다.
**지금 코드에 있는 것**과 **아직 없는 것(제안)**을 나눠 적었다. 제안은 팀 검토 전 초안이다.

- 기준 코드: `app_pages/chatbot.py`, `source/core/chat_parse.py`, `source/core/chat_guard.py`, `source/core/llm_ollama.py`, `source/core/law_search.py`, `source/core/checkup.py`, `source/core/tax.py`, `source/core/usage.py`
- 기준 문서: 기획안(261022), PRD v0.2, `report/검증/인공지능기본법_검토.md`, `report/검증/조문_코드_대응표.md`, `report/검증/챗봇_종목해석_정답률.md`
- 기본 방향 (기획안): **"한 번에 한 가지만, 전문 용어 없이 고객이 아는 숫자만 물음. 답은 가능한 한 칩으로 받음."**

### v0.2에서 바뀐 것 (2026-10-27 검토 반영)

v0.1의 답변 틀이 기획안의 '전문 용어 없이' 방향에서 멀어졌다는 검토를 받아 고쳤다. 기획안 원문과 코드에 대조해 맞는 지적만 반영했다.

| 검토 지적 | 대조 결과 | 반영 |
|---|---|---|
| 보유 수량 시점 불일치 | 맞음. 기획안은 "공시 주당배당금 × **기준일** 보유 수량", 챗봇 ①은 지금 수량을 받음 | 1-2 |
| 기업 답변 틀이 법률 문서 같음 | 맞음. 기획안 ①은 "고배당기업 명단 여부를 바로 알려 줌"(공시 사실) | 4-1 다시 씀 |
| 가드레일 문구가 법을 단정함 | 맞음. 기획안 "이 원칙은 오인을 줄이기 위한 설계이며 법률 적합성을 확정하지 않음" | 2-3 다시 씀 |
| 종목 질문에도 상담 칩이 나감 | 맞음 (`chatbot.py`가 주제와 상관없이 같은 칩) | 2-3 |
| 조문 찾기(RAG)는 기획안에 없음 | 맞음. 2026-10-22 팀이 수업용으로 더한 기능 | 6장, **결정 필요** |
| 결과 화면에 고객 요약·칩 4개가 없음 | **일부만 맞음.** 요약 줄(판정·최소액 수준·특례 합계·세액)과 다음 확인 일정, 버튼 2개 + 칩 2개(합 4개)는 이미 코드에 있음. v0.1 문서에 안 적었을 뿐 | 4-2 |
| [점검 결과 함께 보내기]·상담 안내 기준 없음 | 맞음 | 4-2 |
| ⑥ 버튼 이름 [다시 입력] | v0.1 문서 오기. 코드는 이미 [고칠게요]. 다만 누르면 ①부터 다시 시작함 | 1-1, 7장 |
| 막혔을 때 칩으로 빠져나오기 | 다시 물을 때와 가드레일 뒤에 질문의 칩은 이미 다시 보임. 실패 횟수 안내만 없음 | 2-2, 7장 |
| '모름' 처리 불분명 | v0.1 문서가 불분명했음. 코드는 이미 '모름'이 있으면 분리과세 세액만 보여 줌(`tax.SEPARATE_ONLY`) | 3장 |
| 우선주 이름 맞추기 | 맞음. DB에 우선주 코드는 있으나(`pref_stock_codes`) 회사 이름 맞추기(`name_index`)에는 연결 안 됨 | 3장 |
| 진행 상황 표시 | 단계 알약(① 종목 … ⑥ 확인)은 이미 있음. "3/5" 같은 숫자는 없음 | 7장 |

v0.1에서 확정했던 답변 틀(법 조항을 앞세운 가드레일 문구, 기업 판정 문구)은 이 검토로 바꾼다. 원문을 고치지 않고 그대로 보여 준다는 원칙은 유지한다(6-1).

## 0. 용어: "탐지 구조"는 무엇이라 부르나

| 부르는 이름 | 이 챗봇에서 하는 일 | 코드 |
|---|---|---|
| **가드레일 (Guardrail)** | 챗봇이 하면 안 되는 답을 막는 장치 전체를 묶어 부르는 말 | 아래 셋 |
| 입력 가드레일 · 주제 필터 (Topic filter) | 세법 해석·절세·종목 추천·주가 질문을 **단어 규칙으로 찾아내** 고정 문구로 답함 | `source/core/chat_guard.py` |
| 출력 검증 (Output validation) | AI가 뽑은 값을 JSON 모양 → 값 범위 → 회사 목록 순으로 다시 검사 | `llm_ollama.sanitize`, `chat_parse.validate_*` |
| 근거 대조 · 환각 탐지 (Grounding check) | AI가 돌려준 회사 이름이 고객 문장에 **실제로 있는지** 확인, 없으면 거절 | `Parser.holdings` |

발표·문서에서는 **"가드레일: 입력 주제 필터 + 출력 검증 + 근거 대조"**라고 쓰면 된다.

## 1. 전체 흐름 (챗봇 로직)

```
고객 입력
  │
  ├─ [입력 가드레일] 세금 줄이는 법·종목 질문? ──예──▶ 쉬운 고정 문구 (2-3) → 하던 질문과 그 칩 다시
  │
  ├─ 단계 0 (진입): 진입어 → add-on 카드 / 보유 종목 문장 → 바로 ①로 / 그 밖 → 안내 문구
  ├─ 단계 1~5 (문답): 규칙 해석 → 실패하면 AI(qwen3.5:4b) → 같은 검사 → 통과해야 다음 질문
  ├─ 단계 6 (입력 확인): 입력 요약 표 + 'AI가 읽은 값' 표시 → [맞아요]/[고칠게요]
  └─ 단계 7 (결과): 한 줄 요약 → 고객 요약 → 종목 카드(펼치기) → 연결 버튼·칩
```

(지금 코드에는 가드레일 앞에 '조문 찾기 모드'가 있다. 6장에서 빼는 쪽을 제안한다.)

원칙 네 가지:
0. **계산은 해 주고, 판단은 사람에게 연결한다.** 고객 입력으로 계산한 참고값을 보여 주고, 세무 판단은 자산관리서비스(제휴 세무법인)로 연결한다 (2-1).
1. **질문 순서와 칩은 코드로 고정한다.** AI가 다음 질문을 고르지 않는다.
2. **AI는 값 뽑기에만 쓴다.** 답변 문장, 판정, 세액은 AI가 만들지 않는다.
3. **숫자는 코드로 계산한다.** 판정 근거는 조문 대응표에 고정 연결하고, 화면에는 조문 번호 대신 쉬운 말을 쓴다. 조문은 [근거 보기] 안에 둔다.

### 1-1. 문답 단계

| 단계 | 질문 | 해석 방식(kind) | 특이 처리 |
|---|---|---|---|
| ① | 어떤 종목을 몇 주 갖고 계세요? | `holdings` | 회사 이름을 DB 638사 + 가상 2곳과 맞춤. 수량 시점은 1-2 |
| ② | 예금·채권 이자는 1년에 얼마쯤인가요? | `amount` | [없음]·[모름]. 구간 칩 제안(7장) |
| ③ | 이 종목들 말고 받는 배당이 있나요? | `other_dividend` | [국내 주식]·[해외주식·ETF·펀드]·[없음], 고르면 금액 |
| ④ | 근로소득 말고 사업·연금·기타소득이 있나요? | `yesno` | '있음'이면 ⑤를 건너뛰고 분리과세 세액만 |
| ⑤ | 원천징수영수증의 과세표준 금액을 알려 주세요 | `base` | [근로소득 없음]·[모름]·[영수증 보는 법]. 구간 칩 제안(7장) |
| ⑥ | 입력하신 내용이 맞나요? | - | [맞아요]·[고칠게요]. AI가 읽은 항목에 꼬리표 |
| ⑦ | 점검 결과 | - | 계산 엔진 |

### 1-2. 보유 수량 시점 (꼭 고칠 것)

- **문제**: 기획안의 특례배당소득 계산은 "공시 주당배당금 × **기준일** 보유 수량"이다. 챗봇 ①은 지금 갖고 있는 수량을 받는다. 2025 결산배당 기준일 뒤에 산 주식은 그 배당을 받지 못했는데, 지금 수량으로 계산하면 특례배당소득과 세액이 부풀어 나온다.
- **제안 (둘 중 하나, 결정 필요)**
  - 가. 질문을 기준일 기준으로 바꾼다. 예: "① 올해 봄 배당을 받을 때 어떤 종목을 몇 주 갖고 계셨어요?" 고객이 기준일을 몰라도 답할 수 있게 "올해 봄 배당 받을 때"처럼 쉬운 말로 묻는다.
  - 나. 질문은 그대로 두고, 결과의 세액 옆에 가정을 적는다. 예: "지금 수량을 올해 배당 기준일에도 갖고 계셨다고 가정한 계산이에요."
- 최소한 나는 바로 넣는다(문구만 추가). 가는 질문이 길어지므로 팀이 정한다.

## 2. 제공 범위와 제한

### 2-1. 챗봇이 하는 것

세무사법 제2조(세무대리 업무)를 고려하더라도 아래 두 가지는 제공한다. 챗봇은 세무 판단을 대신하지 않고, **고객이 넣은 숫자로 계산만** 하며, 판단이 필요한 일은 **사람이 하는 세무서비스로 연결**한다.

| 제공 기능 | 범위 | 지금 구현 |
|---|---|---|
| 고객 입력에 의한 계산 | 고객이 입력한 보유 종목·이자·배당·과세표준으로 요건 판정, 최소 필요 배당액, 세액 차이를 계산. "참고용 모의 계산 · 가정에 따른 참고값"으로 표시하고, 신청 여부는 권하지 않음 | `core.checkup.run_checkup`, 결과 화면 |
| 세무서비스 연결 (자산관리서비스 연결) | 세무 판단·신고가 필요하면 은행 자산관리서비스의 제휴 세무법인 상담·신고대행으로 연결. 실제 판단은 세무법인이 함 | [세무상담 예약신청]·[금융소득 종합과세 신고대행 신청] 버튼 (지금은 모형 버튼), 이용 통계 '상담 연결' |

### 2-2. 챗봇이 하지 않는 것

아래 "이유"는 오인을 줄이려는 설계 기준이다. 기획안대로 **법률 적합성을 확정하지 않으며**, 고객에게 보이는 문구에는 법 조문을 쓰지 않는다.

| 제한 | 설계 기준 | 지금 구현 |
|---|---|---|
| 세법 해석·절세 방법·신청 권유를 하지 않음 (계산은 2-1대로 제공) | 세무사법 제2조 고려 | `chat_guard.TAX_ADVICE` 고정 문구(2-3) |
| 종목 추천·목표주가·주가 예측을 하지 않음 | 자본시장법 제6조 제7항 고려 | `chat_guard.STOCK_ADVICE` 고정 문구(2-3) |
| AI가 답변 문장을 만들지 않음 | 위 두 원칙 + 인공지능기본법 검토 | AI 출력은 JSON 값뿐, 화면 문장은 `source/core/sample_data.py`에 고정 |
| 고객 입력을 밖으로 보내지 않음 | 기획안 "서버 내 처리" | Ollama 주소는 localhost만 허용(`make_llm`) |
| 입력값을 저장하지 않음 | 개인정보 최소 수집 | 세션 메모리에만 둠. 이용 통계는 횟수만(`source/core/usage.py`) |
| '유리/불리'·'신청하세요' 같은 판단 표현을 쓰지 않음 | 세무사법 고려 | 결과는 "계산상 세액 차이 · 가정에 따른 참고값"으로 표시 |

### 2-3. 가드레일에 걸렸을 때의 고정 답변

법 조문을 들이밀지 않고, 할 수 있는 일(계산)과 갈 곳(세무 전문가)을 쉬운 말로 알려 준다. AI가 만들지 않고 코드에 고정한다.

| 주제 | 고정 답변 | 이어서 보여 주는 것 |
|---|---|---|
| 세금 줄이는 법·신청 여부·세법 해석 | 세금을 줄이는 방법이나 신청 여부는 세무 전문가가 함께 봐 드려요. 계산은 계속 도와드릴게요. | [세무상담 예약신청] 칩 → 하던 질문과 그 칩 다시 |
| 종목 추천·주가 전망 | 종목 추천이나 주가 전망은 알려 드리지 않아요. 하던 점검을 이어서 할게요. | 상담 칩 없이 하던 질문과 그 칩 다시 |

- 지금 코드(`chat_guard.FIXED_REPLY`)는 다른 문장이고, 종목 질문에도 상담 칩이 나간다(`chatbot.py`의 `guard` 그리기). 둘 다 바꾸는 코드 수정과 `source/tests/test_chat_guard.py` 수정이 남아 있다.
- 가드레일 뒤에 하던 질문이 마지막 메시지로 다시 나오므로, 그 질문의 칩도 이미 다시 보인다(`_reask`). 이 동작은 유지한다.

**값의 범위 제한** (`source/core/chat_parse.py`)
- 금액: 0원 이상 1조 원 이하 (`MAX_AMOUNT`)
- 주식 수: 1주 이상 10억 주 이하 (`MAX_SHARES`)
- AI 호출: 8초 넘으면 포기 (`TIMEOUT_SEC`)

**제안 (아직 없음)**
- [ ] 입력 길이 제한: 한 번에 200자 정도로 자르기. 지금은 길이 제한이 없어 긴 글이 AI까지 갈 수 있다.
- [ ] 같은 질문에서 연속 3번 실패하면 "아래에서 골라 주세요"와 함께 칩만 다시 보여 주기 (꼭 넣기).

## 3. 예외 처리

| 상황 | 챗봇 반응 | 코드 |
|---|---|---|
| 규칙으로 못 읽음 + AI 꺼짐 | "{오류} 다시 알려 주세요." + 같은 질문 다시 | `PARSE_RETRY` |
| Ollama 꺼짐·시간 초과·깨진 JSON·모양이 틀린 값 | 빈 값 → 위와 같이 다시 묻기. 오류 화면을 띄우지 않음 | `make_llm`의 `except` |
| Ollama가 꺼져 있다 다시 켜짐 | 60초마다 다시 확인 | `RECHECK_SEC` |
| 목록에 없는 회사 | "찾지 못했어요. 혹시 ○○ 말씀인가요?" (후보 최대 3개, **자동으로 고르지 않음**) | `match_company`, `not_found_message` |
| AI가 문장에 없는 회사 이름을 돌려줌 | "'○○'을(를) 입력하신 문장에서 확인하지 못했어요" | `Parser.holdings` |
| 이자·다른 배당·과세표준 중 '모름'이 있음 | 기획안대로 **세액 비교를 하지 않고 분리과세 세액만** 보여 줌. 모르는 항목 이름과 세무상담 안내를 함께 표시 | `tax.compare` → `SEPARATE_ONLY` |
| ④ 다른 소득 '있음' | ⑤를 묻지 않고 분리과세 세액만 | `OTHER_INCOME_STEP` |
| 같은 회사를 두 번 적음 | 주식 수를 더함 | `validate_holdings` |
| 계산 자료가 모자란 회사 | 판정 보류 + 이유 한 줄 | `core.judgement` |

**확인 필요**
- [ ] **우선주**: 기획안에는 우선주 연결이 있다. DB에는 상장 우선주 코드(`pref_stock_codes`)가 있지만, 회사 이름 맞추기(`company_repo.name_index`)는 보통주 이름과 종목코드만 연결한다. "삼성전자우 100주"를 넣으면 지금은 목록에 없다고 나온다. 우선주 이름·코드를 같은 회사로 연결하고, 우선주 주당배당금을 따로 쓰는지 확인하기.
- [ ] ④ `yesno`는 문장에 '있'이 들어가면 '있음'으로 본다. "예전엔 있었는데 지금은 없어요"는 '있음'으로 잘못 읽힌다. 둘 다 있으면 다시 묻도록 바꾸기.

## 4. 답변 구조화

챗봇의 모든 말은 **정해진 틀(kind)** 중 하나로만 나간다. AI가 틀을 고르지 않는다. 화면 문장에는 조문 번호·'사업연도' 같은 전문 용어를 쓰지 않고, 필요하면 [근거 보기] 안에 둔다.

| 틀 (kind) | 언제 | 내용 |
|---|---|---|
| `text` | 질문·안내 | `source/core/sample_data.py`의 고정 문장 |
| `addon` | 진입 | add-on 카드 + 칩 |
| `holding` | ① 통과 후 | 기업 답변 틀(4-1) + "회사 공시" 꼬리표 |
| `guard` | 가드레일 걸림 | 쉬운 고정 문구(2-3) (+ 세금 주제일 때만 상담 칩) |
| `confirm` | ⑥ | 입력 요약 표 + "AI가 읽은 값" 꼬리표 |

### 4-1. 고객이 기업을 입력했을 때의 답변 틀

기획안 ①은 "고배당기업 명단 여부를 바로 알려 줌"이다. 그래서 ①에서는 **회사 공시 사실**을 먼저 말하고, 팀이 계산한 다음 해 판정은 단정하지 않고 **조건**으로 말한다. 고객이 궁금한 것은 "내가 언제 받는 배당이 분리과세 되나"이므로 연도는 받는 시점으로 말한다.

> ○○은 올해 봄 배당이 분리과세 대상이었어요(회사 공시). 내년 봄 배당도 대상이 되려면 배당성향 40% 이상 등이 필요해요. [근거 보기]

| 경우 (2025 공시) | 문장 |
|---|---|
| 명단에 있음 | ○○은 올해 봄 배당이 분리과세 대상이었어요(회사 공시). 내년 봄 배당도 대상이 되려면 (조건)이 필요해요. |
| 명단에 없음 | ○○은 올해 봄 배당이 분리과세 대상이 아니었어요(회사 공시). 내년 봄 배당이 대상이 되려면 (조건)이 필요해요. |

- (조건)은 판정 엔진이 쓴 경로에 맞춰 고정 문장 중 고른다. 예: "배당성향 40% 이상", "배당성향 25% 이상이면서 배당금이 10% 이상 증가", "배당금이 2024년보다 줄지 않음". AI가 쓰지 않는다.
- 2026 사업연도 판정(충족·미충족·보류)과 최소 필요 배당액은 결과 화면 종목 카드에서 "현재 해석 기준" 꼬리표와 함께 보여 준다. ①에서는 "해당합니다"처럼 단정하지 않는다.
- [근거 보기]를 누르면 조문 이름·번호·원문과 KIND 공시 링크를 보여 준다(6-1, `report/검증/조문_코드_대응표.md`).
- '올해 봄 배당'은 2025 결산배당(2026년 봄 수령), '내년 봄 배당'은 2026 결산배당(2027년 봄 수령)을 뜻한다. 중간·분기배당이 있는 회사는 [근거 보기]에서 나눠 보여 준다.
- 지금 코드는 "{name}는 고배당기업 목록(2026-10-19 기준)에 있어요." 한 줄이다(`HOLDING_NOTE`). 이 틀로 바꾸는 코드 수정이 남아 있다. 조사 '은/는'은 받침에 따라 코드로 고른다.

**한 줄 요약 (제안)**
> 보유 3종목 중 2종목은 올해 봄 배당이 분리과세 대상이에요. 신청하면 계산상 세금이 약 ○○만 원 달라져요(가정: ○○).

- 숫자는 모두 계산 엔진 값을 그대로 넣는다. "달라져요"는 방향(늘거나 줄거나)을 단정하지 않는 표현이며, 세액 표시는 지금처럼 "계산상 세액 차이 · 가정에 따른 참고값"을 유지한다.

**AI 출력 구조** (`llm_ollama.SCHEMAS`)
- `amount`: `{"amount": 정수 또는 null, "unknown": true/false}`
- `holdings`: `{"holdings": [{"company": 문자열, "shares": 정수}, ...]}`
- Ollama `format`에 스키마를 넣어 이 모양으로만 받는다. 생각 단계는 끄고(`think: false`), `temperature: 0`.

## 5. 답변 정확성

### 5-1. 정확성을 지키는 겹

```
규칙 해석 ─(실패)─▶ AI 해석 ─▶ JSON 모양 검사 ─▶ 근거 대조 ─▶ 값 범위·회사 목록 검사 ─▶ 고객 확인(⑥)
```

| 겹 | 막는 오류 |
|---|---|
| 규칙 먼저 | 쉬운 문장을 AI에 맡겨 생기는 오류. 규칙이 읽는 문장을 늘려 AI 사용을 줄임 |
| JSON 모양 검사 | 설명 문장, 깨진 출력 |
| 근거 대조 | AI가 지어낸 회사 이름 (예: 삼성전기 → 삼성전자) |
| 값 범위·회사 목록 | 음수, 단위 실수, 목록에 없는 회사 |
| 고객 확인 | 위에서 못 막은 주식 수·금액 오류 |

입력 해석이 맞아도 **입력의 뜻이 계산과 다르면** 결과가 틀린다. 1-2의 보유 수량 시점이 그런 경우다.

### 5-3. 남은 빈 곳 (제안)

- [ ] **금액은 근거 대조가 없다.** AI가 읽은 금액이 문장과 맞는지 확인하지 않는다. 예: 문장에 숫자나 한글 숫자 단어가 하나도 없는데 AI가 0보다 큰 금액을 돌려주면 받지 않기.
- [ ] **금액 문장 정답률을 아직 재지 않았다.** "오백만 원쯤", "천오백 정도", "1억 좀 넘어요" 같은 문장 묶음으로 재기. 구간 칩(7장)을 넣으면 금액을 칠 일이 줄어 이 위험도 준다.
- [ ] 완전히 처음 보는 문장 묶음을 하나 더 만들어, 고치지 않고 한 번만 재기.
- [ ] 모델이나 Ollama 판이 바뀌면 다시 재기.
- [ ] 가상 고객 5건을 챗봇 문답부터 결과까지 끝까지 돌린 기록 남기기 (`archive/old_docs/기획안_대비_현황.md` 28행).

| **⑤ 과세표준 구간 칩**: [1,400만 원 이하] [1,400만~5,000만] [5,000만~8,800만] [8,800만~1.5억] [1.5억 초과] | 대부분 원천징수영수증을 갖고 있지 않아 가장 많이 멈추는 곳. 세율 구간만 알아도 세액 차이를 대략 계산할 수 있음. 결과에 "구간 기준 추정" 꼬리표 | 금액·[근로소득 없음]·[모름]·[영수증 보는 법]만 |
| **② 이자 구간 칩**: [500만 원 이하] [500만~1,000만] … | 타이핑이 거의 없어지고 AI 금액 해석 위험도 줄어듦 | [없음]·[모름]만 |
| **⑥ 항목별 [고치기]** | 지금 [고칠게요]는 ①부터 다시 시작한다. 처음부터 다시 하면 대부분 나간다. 틀린 항목만 다시 묻고 ⑥으로 돌아오기 | `_on_confirm`이 답을 모두 지우고 ①로 |
| **진행 숫자**: "3/5" | 끝이 보이면 덜 나간다 | 단계 알약(① 종목 … ⑥ 확인)은 있음. 숫자만 더하면 됨 |
| **결과는 한 줄 요약부터** | 기획안 '고객 요약'과 맞춤 | 4-2 |
| **막혔을 때 칩으로 빠져나오기** | 3번 실패하면 "아래에서 골라 주세요"로 칩을 가리키기(2-2 제안) | 다시 물을 때와 가드레일 뒤에 질문의 칩은 이미 다시 보임. 실패 횟수를 세는 안내만 없음 |

**구간 칩 확인 필요**
- [ ] 구간 칩으로 받은 값은 정확한 금액이 아니다. 구간 안 어느 값을 쓸지(가운데 값, 아래 끝·위 끝 두 번 계산해 범위로 보여 주기 등)를 정하고 `source/core/tax.py`에서 계산하기. 경계 1원 아래·경계·1원 위 테스트도 함께.
- [ ] 1.5억 위에도 3억·5억·10억 세율 구간이 있다. [1.5억 초과] 하나로 묶을지, 그 위 고객은 금액 입력을 권할지 정하기.

## 8. 가드레일 (탐지 구조) 자세히

### 8-1. 입력 주제 필터 (`source/core/chat_guard.py`)

- 띄어쓰기를 지우고 단어 목록에 걸리면 주제를 돌려준다.
- 세법 해석·절세: "절세", "세금 줄", "유리", "불리", "신청해야", "어떻게 해야", "세법 해석", "탈세" 등 15개
- 종목·주가: "추천", "살까", "사야 할까", "사도 돼", "팔아도 돼", "매수", "전망", "예측", "목표주가", "좋은 회사" 등 25개. '주가'·'사야' 한 단어로는 걸지 않는다("주가가 왜 떨어져?" 같은 개념 질문과 '회사야'가 막혀서, 2026-10-29 `report/설계/챗봇_질문목록.md`)
- 걸리면: 2-3의 쉬운 고정 문구 → (세금 주제만) [세무상담 예약신청] 칩 → 하던 질문과 칩 다시. 상담 칩을 누르면 이용 통계 '상담 연결' +1.
- 결과 화면(단계 7)에서는 걸지 않는다.

**한계와 제안**
- [ ] **잘못 걸림**: "어떻게 해야 해요?"(입력 방법을 묻는 말)도 세법 질문으로 걸린다(2026-10-27 실행 확인). 걸리면 안 되는 문장 묶음을 `source/tests/test_chat_guard.py`에 넣기.
- [ ] **못 걸림**: "세금 덜 내는 법"은 빠진다(2026-10-27 실행 확인). "이거 사도 돼요?"는 2026-10-29에 고쳤다. 걸려야 하는 문장 묶음을 더 모아 두 비율을 재기.
- [ ] 주제 판별에 AI를 쓰지 않고 단어 목록을 늘리는 쪽으로 간다 — 팀 확인 필요.

### 8-2. 출력 검증과 근거 대조

- 5-1 표 참고. AI 출력은 스키마 → `sanitize` → `validate_*` → 근거 대조를 거친 뒤에만 계산에 들어간다.
- "앞의 지시를 무시하고…" 같은 문장이 들어와도 AI 출력은 금액 하나·종목 목록 하나로만 받으므로, 화면에 다른 문장이 나갈 길이 없다.

### 8-3. 기록 (로그)

- `Parser.log`에는 "어느 항목을 규칙/AI로 읽었고 통과했는지"만 남긴다(예: `amount:AI:True`). 입력 문장과 값은 남기지 않는다.
- 이용 통계는 점검 시작·완료·상담 연결 횟수만 센다.
