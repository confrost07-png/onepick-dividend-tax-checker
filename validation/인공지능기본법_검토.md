# 인공지능기본법 관련 검토 (챗봇 add-on)

> **법률 자문이 아닌 조사 결과예요.** 공개 자료(법령 안내, 정부 보도, 로펌 자료)를 정리해 우리 프로토타입 설계에 대입한 것이에요. 실서비스 도입 때는 법령 원문과 A은행 준법·법무 검토가 필요해요.

- 작성일: 2026-10-22
- 대상: 챗봇 add-on(보유 종목 점검·예상 세금 비교). 데이터 분석 화면은 AI를 쓰지 않아 이 검토의 대상이 아니에요.
- 관련 기획안 문장: "고객 입력은 서버 내 Ollama로만 처리하고 외부 LLM API로 보내지 않음. 챗봇 첫 카드에 '입력 문장 해석에 AI를 사용합니다'를 표시함(인공지능기본법 투명성 의무 고려)"
- **변경 이력**: 2026-10-22 한때 OpenAI API(`gpt-4o-mini`)로 바꿨으나(크레딧 없음으로 실제 호출 안 됨), **2026-10-23 기획안대로 서버 안 Ollama로 되돌림.** 고객 입력은 외부로 보내지 않아요.

## 2. 우리 서비스에 대입한 결과

| 쟁점 | 판단 | 근거 |
|---|---|---|
| 고영향 인공지능인가 (법 제2조 제4호) | 해당하지 않을 가능성이 높음 | 고영향 영역에는 채용·대출 심사처럼 개인의 권리·의무에 중대한 영향을 주는 판단이 들어감. 우리 챗봇은 세액 참고값만 보여 주고 승인·거절 같은 결정을 하지 않음. 계산은 코드가 하고, AI는 문장에서 숫자만 읽음. 신청 여부는 제휴 세무법인 상담에서 정함 |
| 생성형 AI 사전 고지 (법 제31조 제1항) | 적용됨 → 반영함 | A은행이 생성형 AI가 들어간 서비스를 최종 이용자에게 제공함. 가이드라인은 챗봇에 대해 이용 전 안내나 화면 내 상징(로고)을 인정함 |
| 생성물 표시 (법 제31조 제2항) | 대체로 해당 없음, 보수적으로 보완함 | 챗봇 답변은 모두 정해 둔 문장이고 숫자는 코드가 계산함. 다만 ⑥ 입력 요약의 값은 AI가 문장에서 읽은 값일 수 있어 따로 표시함 |
| 딥페이크 고지 (법 제31조 제3항) | 해당 없음 | 이미지·음성·영상을 만들지 않음 |
| 자동화된 결정 (개인정보보호법 제37조의2) | 해당하지 않을 가능성이 높음 | 이 조항은 완전히 자동화된 시스템이 권리·의무에 중대한 영향을 주는 결정을 할 때 적용됨. 우리는 결정이 없고, 고객이 ⑥에서 값을 확인한 뒤에만 계산함 |
| 금융분야 AI 가이드라인 | 따르는 것이 바람직함 | 회사가 스스로 위험등급을 정해 차등 관리하라고 권고함. 외부 API·SaaS형 AI를 쓰면 보안과 망분리 대체 통제를 점검해야 함 |

## 3. 자체 평가 기록

### 3-1. 고영향 인공지능이 아니라고 본 근거
1. **사용 영역**: 세액 참고 계산과 상담 연결 안내예요. 대출 심사·채용 같은 고영향 영역이 아니에요.
2. **결정 여부**: 승인·거절·한도 같은 결정을 하지 않아요. 결과 화면에는 '계산상 세액 차이'만 중립적으로 보여 주고 신청을 권하지 않아요.
3. **AI의 역할**: AI(이 컴퓨터의 Ollama `qwen3.5:4b`)는 고객이 친 문장에서 금액·종목·수량을 읽어 JSON으로 바꾸는 일만 해요. [관련 조문 찾기]의 `bge-m3`는 조문 문단을 고르기만 해요. 요건 판정·최소액·세액은 모두 규칙 코드가 계산해요.
4. **사람 확인**: AI가 읽은 값도 ⑥ 입력 요약에서 고객이 [맞아요]를 눌러야 계산에 쓰여요.
5. **추가 확인 방법**: 법 제33조에 따라 과기정통부에 고영향 인공지능 해당 여부 확인을 요청할 수 있어요. 실서비스 도입 전에 이용하는 것을 권해요.

### 3-2. 금융분야 AI 가이드라인 기준 위험등급: 저위험으로 판단
- 고객의 금융거래 승인·가격·한도에 영향을 주지 않아요.
- AI가 틀려도 ⑥ 확인 단계에서 걸러지고, 값 범위 검사(`source/core/chat_parse.validate_*`)를 통과해야만 쓰여요.
- 고객 입력을 외부로 보내지 않아요. 입력 해석과 조문 찾기 모두 서버 안 Ollama(주소는 localhost만 허용)에서 처리해서, 외부 API 사용에 따른 망분리 대체 통제 문제가 생기지 않아요.
- 입력값을 저장하지 않아요. 세션 메모리에서만 쓰고 로그에는 해석 방식(규칙/AI, 성공 여부)만 남겨요.

### 3-3. 고지 위치와 문장
- **위치**: 내 배당 점검 화면(`/check`) 첫 인사 말풍선 아래. 고객이 첫 질문에 답하기 전에 보여요.
- **문장(웹)**: "입력 문장 해석, 보유 종목·원천징수영수증 사진 읽기, 금융 상식 답 고르기, 관련 조문 찾기에 AI를 사용합니다. 입력하신 내용은 은행 서버 안에서만 처리하며 외부로 보내지 않습니다. 계산 결과는 참고용입니다."
- **문장(사진 입력이 없는 화면)**: 위 문장에서 '보유 종목·원천징수영수증 사진 읽기,'만 뺀 문장
- **코드**: `source/core/sample_data.py`의 `ADDON_NOTE`·`WEB_ADDON_NOTE` → `GET /api/chat/script`의 `ai_note` → `app/web/src/pages/Check.tsx`
- **테스트**: `source/tests/test_api.py::test_script_has_ai_notice_mark_and_receipt_guide`
- 2026-11-04: 사진 읽기·금융 상식 답 고르기가 더해져 문장을 지금 코드에 맞춤

## 4. 설계 반영 현황

### 이미 반영된 것 (기획안 그대로)
- 첫 카드의 AI 사용 고지
- 고객 입력을 외부 LLM으로 보내지 않음, 입력값 미저장
- AI는 값 추출만, 계산·검사는 코드
- 세법 해석·절세·권유 표현을 쓰지 않음
- 계산 전 사람 확인([맞아요]·[고칠게요])

## 5. 확인하지 못한 것
- **법 제2조 제4호 원문**: 고영향 영역의 정확한 문구는 국가법령정보센터 페이지가 웹으로 열리지 않아 직접 읽지 못했어요. 로펌 자료의 요약으로만 확인했어요.
- **시행령 조문 번호**: 투명성 조항은 입법예고 때 제22조였고, 현행본에는 제23조로 나와요. 인용하기 전에 원문을 봐야 해요.
- **계도기간 종료일**: 공식 발표를 확인하지 못했어요.
- **실서비스 준법 검토**: 이 문서는 프로토타입 설계 기준이에요.
- **모델 라이선스**: 인공지능기본법과는 별개 문제예요. 입력 해석 모델은 비상업 라이선스인 EXAONE 3.5(1.1 - NC) 대신 Apache 2.0인 `qwen3.5:4b`로 바꿨어요. 조문 찾기의 `bge-m3`는 MIT예요. 실제 한국어 값 뽑기 정확도는 아직 시험하지 않았어요.
